# 弱い保有と強い候補の入れ替えの検証 2026-10-24

手順・候補・採用の基準は、検証の前に `rules/candidates/PROTOCOL-2026-10-24-swap.md` に書いてコミットした (a9654cc)。
結果を見た後で、仕様と基準は変えていない。
結果ファイル: `reports/backtest/2026-10-24-swap-yearly/` (年ごと)、`reports/backtest/2026-10-24-{v3,w1-*,w2-*,w3-*}-split/` (学習 / 検証)。

## 結論

- **事前に決めた基準を満たした候補はなく、採用候補はなし。** 3案とも「各年の最大下落の平均が指数 50/50 より小さい」を満たさず、学習期間のシャープレシオも v3 をわずかに下回った
- ただし **w1 (差20ポイントで入れ替え) はリターンを大きく上げた** (8年通算 +110% → +254%、最悪の年 -10.9% → -2.5%、検証期間のシャープ 0.29 → 0.80)。代わりに下落が少し大きくなった (各年の最大下落の平均 14.7% → 16.4%)
- 「結論は出さず、実データで確かめる」ため、w1 をフォワードテストに参考として加えた (実際の口座のルールは v3 のまま)

## 方法

- 候補はどれも v3 (`config/rules.yaml`) に `swap` の項目を足しただけ。枠 (8銘柄) が埋まっているときだけ動く
  - 買い条件を満たす候補のうち60日リターンが一番大きい銘柄 (候補1位) と、買って28日以上たった保有のうち60日リターンが一番小さい銘柄 (一番弱い保有) を比べる
  - 差が基準以上なら、翌営業日の寄付きで一番弱い保有を全部売り、候補1位を買う (1日1組まで)
  - w1: 差20ポイント / w2: 差40ポイント / w3: 差20ポイント、ただし一番弱い保有の60日リターンがマイナスのときだけ
- 期間・母集団・約定条件・決算日のデータは、決算の検証 (`2026-10-24-earnings.md`) と同じ (2019〜2026 の8年を `--years 9` のデータで集計)

## わかったこと

1. **入れ替えはリターンを大きく上げる。** 3案とも8年通算で v3 を大きく上回り、v3 が苦手だった 2024・2025・2026年で特に差が出た (2025年: v3 -10.9%、w1 +0.2%)。v3 は一度枠が埋まると、勢いを失った銘柄を損切りかトレーリングまで持ち続けるので、その間に強い銘柄を取り逃していた
2. **代わりに下落が大きくなる。** 入れ替えで常に勢いの強い銘柄を持つため、相場が反転したときに一緒に下がる (学習期間の最大下落 16% → 23%)。これは月次で全部入れ替える型 (momentum-12-1) と同じ弱点で、程度はそれより小さい
3. **w1 は基準にあと少しで届かなかった。** 学習期間のシャープは v3 とほぼ同じ (1.218 対 1.221) で、検証期間では大きく上 (0.80 対 0.29)。不合格の主因は最大下落の平均 (16.4% 対 指数 15.0%)
4. **入れ替えの回数**: w1 は8年で約175回 (年に約22回、月に2回弱)。NISA の枠は買うたびに使うので、口座の規模が大きくなると年間の枠 (240万円) に当たりうる。今の規模 (約44万円) なら問題ない

## 注意
- 母集団が「今の大型株」なので、強い銘柄を追いかける型ほど生き残りバイアスで良く見えやすい。w1 のリターンの上げ幅は割り引いて見るべき
- 3案の中で一番良かった w1 を選んでフォワードテストに回すこと自体が、少しだけ「過去に合わせた選択」になる
