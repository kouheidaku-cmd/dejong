# 売買ルール

このファイルは**人間が管理する**。Claude は読むだけで、変更したい場合はレポートで提案する。
ルールは次の3層に分かれる。上の層ほど強い。

| 層 | 中身 | どこにあるか | 誰が守らせるか |
|---|---|---|---|
| 1. 絶対の上限 | 1銘柄の比率、現金比率、空売り禁止など | `config/settings.yaml` の `risk` | コード (`trader/risk.py`)。違反は注文案にならない |
| 2. 機械ルール | いつ買う・いつ売る・何株 | `config/rules.yaml` | コードが毎日シグナルを出す。**バックテストで検証できるのはこの層だけ** |
| 3. 裁量ルール | ニュース・決算など数字にできない判断 | このファイルの下の方 | Claude。シグナルを**見送る**ことと、仮説が崩れたときの**売り**だけ許す |

## 共通の前提
- 対象: 楽天証券の口座全体 (日本株・米国株)。投資信託は対象外
- 時間軸: 数週間〜数か月のスイング。判断は終値、発注は人 (米国株はその日の夜、日本株は翌朝の寄付き)
- 日本株はかぶミニで1株単位。現金がほぼないので、買いは売却代金の範囲で行う (入れ替え)
- 2026-10-20 時点の保有5銘柄は「今日を起点にする」: 損切り・利確・トレーリングストップの基準を
  取得単価ではなくこの日の価格にする (`state/sync/2026-10-20.yaml` の `rule_ref`)。
  損益の計算には実際の取得単価を使う

## 口座の作り: コア・サテライト (2026-11-10 に人が決定)
- **コア**: 口座の大半は指数の投資信託 (日経平均・S&P500 など) で持つ。このシステムは売買しない
- **サテライト**: 残りをこのシステムで売買する (下の機械ルール)
- 理由: 8年の検証で、v3 の成績は「同じだけ指数を持った場合」とほぼ同じで、上回っていない (`reports/rules/2026-11-10-review.md`)
- **割合の決め方** (人から任されて 2026-11-10 に決定):
  - 今の株の口座 (約40万円) を、そのままサテライトにする。指数に移すために今の株を売ることはしない
    (売っても NISA の枠は戻らず、売買の回数も増えるため)
  - **これから入れるお金は、すべてコアに入れる** (つみたて投資枠で、S&P500 か全世界株式などの低コストの指数の投資信託。金額と商品は人が決める)。
    このシステムの口座には追加で入金しない
  - コアが口座全体の7割になるまで、これを続ける
  - サテライトを増やすのは、フォワードテストで「同じ持ち高の指数」を上回ったときだけ (2027年1月下旬に見直す)

## ドローダウン停止は使わない (2026-11-10 に人が決定)
- 以前は「総資産が最高値から 15% 下げたら新規買いを停止」だった。検証すると、止まったあと再開できなくなる作りで、
  再開できるように直しても成績を下げるだけだった (v3 の8年: 停止なし +128% / 直近365日の最高値で停止 +71%、最大下落は小さくならない)
- `settings.yaml` の `max_drawdown_pct` を null にした。バックテストも停止なしで走る
- ドローダウンは日次レポートに出し続ける (直近365日の最高値から)。10% を超えたら週次の振り返りでルールを見直す。緊急時は `STOP` ファイルで全注文を止める

## NISA (2026-10-22 確認)
- 保有株と投資信託は**すべて NISA 成長投資枠**。新しく買う株も、枠が残っている限り成長投資枠で買う
- 売却益は非課税なので、利益の出ている銘柄を売っても税金のコストはない
- 損失は他の利益と相殺できない (損切りのルール自体は変えない)
- 買付は年間枠 (成長投資枠 240万円/年) を使う。売ってもその年の枠は戻らない。日次レポートでその年の買付額の合計を意識する
- 2026年の成長投資枠の残りは 1,292,350円 (10/22 時点、`settings.yaml` の `nisa`)。口座の規模 (約44万円) なら年内に超える心配はない。2027年1月に枠が新しくなる
- つみたて投資枠 (年120万円) は未使用。株の売買ルールとは別に、人が使い道を決める

## 2. 機械ルール (rules.yaml v3 の内容、2026-10-24 から)

**買う** (すべて満たしたとき・ウォッチリストの銘柄だけ・保有中は買い増ししない)
- 上昇トレンド: 終値 > SMA50 > SMA200
- 60日リターンがプラス
- RSI14 が 70 未満 (過熱していない)
- 終値が SMA20 から +8% 以内 (高値づかみ防止)
- その銘柄の市場の指数 (日経平均 / S&P500) が SMA200 より上 (地合いが悪いときは買わない)
- 決算発表日の3営業日前〜当日に約定する新規買いはしない (v3 で追加。保有中の銘柄は決算をまたいで持つ)
- 同時保有は8銘柄まで。候補が多いときは60日リターンの大きい順。1銘柄の目標は総資産の12%

**売る** (上から順に判定)
1. 損切り: 取得単価から -8% → 全部売る
2. トレーリングストップ: 保有中の最高値から -15% → 全部売る
3. 利確: 取得単価から +20% → 半分売る (1回だけ)
- トレンド崩れ (SMA50 割れ) だけでは売らない (v1 では売っていたが、検証で成績が悪かった)

## 3. 裁量ルール (Claude が判断)
- **見送ってよい**: 決算日のデータが取れず決算前か分からない銘柄の新規買い (決算前の新規買いは v3 から機械ルールで止まる) / 悪材料が出ている銘柄の買い / 市場全体が急落している日の買い
- **前倒しで売ってよい**: 週次リサーチの投資仮説が崩れた (業績の下方修正、事業の大きな悪材料など)
- **やってはいけない**: シグナルのない買い / ナンピン / ニュース一発での飛びつき買い / 信用取引・空売り・オプション
- 見送り・前倒しの売りをしたら、理由を日次レポートに必ず書く (後で裁量が効いたか検証するため)

## ルールの直し方 (基準は 2026-11-10 に作り直した)
1. `improve-rules` スキルで、過去データの仮想売買 (バックテスト) と損失トレードの分析をする
2. 案と基準は、検証を走らせる前に `rules/candidates/PROTOCOL-<日付>.md` に書いてコミットする
3. 採用の基準 (`python -m trader phases` で計算。1年の区切りを1月〜12月始まりの12通りに変えて見る):
   - **現行ルールとの比較**: 12通り中10通り以上で通算リターンが現行より高く、かつ12通り中10通り以上で各年の最大下落の平均が現行より大きくない → 採用候補
   - リターンは高いが下落も大きい (またはその逆) → 合否ではなく、差の大きさを示して**人が決める**
   - **同じ持ち高の指数との比較** (指数 50/50 を、ルールと同じだけ持って残りを現金にしたもの): 12通り中10通り以上でリターンが上、かつ下落が大きくない。
     現行ルールにも同じ基準を当てる。これを満たさない間は、サテライトの割合を増やさない
   - 「2ポイント以内」のような細かい線引きは使わない (区切りや偶然で変わる大きさなので)
4. 過去8年のデータは 21案以上を試して使い切っているので、**最終判断はフォワードテスト (3か月以上)** で行う
5. 候補を人が了承したら `rules.yaml` を更新し、`rules_changelog.md` に記録する
6. 実際の売買で損失が出たときも、週次の振り返りで同じ手順にかける
