# surge — 集中モメンタム型の売買システム

既存の `trader/` (daily-trade) とは別に、一から作った売買システム。目的は「4か月で +20%」に届く確率をできるだけ上げること。
発注は人が楽天証券で行う (半自動)。口座の記録 (`state/`) は既存の仕組みと共有し、surge は読むだけ。

## 先に結論 (正直な数字)

過去 21年 (2005-06 〜 2026-11) を、今の口座と同じ条件 (元手 40万円・整数株・片道コスト 0.2%・円換算) で仮想売買した結果:

| | surge | 指数 50/50 | 母集団を均等保有 (※) |
|---|---|---|---|
| 年率リターン | **+20.8%** | +10.8% | +20.1% |
| 最大下落 | **37.5%** | 59.8% | 53.0% |
| 4か月後に +20% 以上だった割合 | **21%** | 5% | 12% |
| 4か月後の中央値 | +6.0% | +4.4% | +7.3% |
| 4か月後にマイナスだった割合 | 31% | 31% | 25% |
| 4か月後に -10% 以下だった割合 | 13% | 10% | 8% |
| 4か月の悪い方 5% / 最悪 | -17% / -30% | -14% / -44% | -13% / -43% |

- **「4か月で +20%」は、このシステムでも5回に1回くらいの出来事。** 指数を持つだけなら20回に1回なので確率は約4倍になるが、
  「狙えば届く」数字ではない。3回に1回はマイナスで終わり、8回に1回は -10% より悪い
- (※) 母集団は「今の」大型株なので、均等に持つだけで年 +20% になる (後知恵の偏り)。surge の年率はこれとほぼ同じで、
  **銘柄選びでリターンが大きく増えているわけではない**。surge が変えているのは、結果のばらつき方
  (大きく勝つ4か月が増える) と、暴落のときの下落 (リーマンショックを含む 2005〜2012年の最大下落は、指数の 60% に対して 37%)
- したがって、これから先の年率は +20% より低く見ておくのが妥当 (偏りのない母集団なら指数に近い水準 + α)
- 詳しい検証は `reports/surge/2026-11-13-validation.md`

## ルール

毎週末に、米国の大型株 144銘柄 (`universe.yaml`) を「過去 3・6・12か月の値上がり率の平均」で順位づけする。

**買う** (週1回)
- 上位から 5銘柄まで。1銘柄は 株 + 現金 の 19% (現金を 5% 残す)
- 終値が 200日線より上で、直近126日の最高値から 15% 以内にいる銘柄だけ (落ちている途中の銘柄は買わない)
- S&P500 が 200日線より下のときは、新しく買わない
- 同じ業種グループは2銘柄まで
- 1株が上限 (約25%) を超える銘柄は飛ばして次の順位へ

**売る**
- 週1回: 順位が 20位より下に落ちた / 終値が 200日線を割った → 全部売る
- 毎日: 買ってからの最高終値から -25% → 全部売る
- 1銘柄が 35% を超えたら 19% まで減らす (伸びた1銘柄に口座を預けない)

**そのほか**
- 持ち続ける銘柄が目標の金額の 60% より小さく、今も買える条件を満たしていれば、目標まで買い増す
- 判定は終値、約定は次の営業日の寄付き
- 絶対の上限は既存の `config/settings.yaml` の `risk` (1銘柄 25%・現金 5%) と `STOP` ファイルに従う
- Claude の裁量は「買いの見送り」だけ (決算直前・買収される側・存続に関わる悪材料)。手順は `.claude/skills/surge-trade/SKILL.md`

日本株は買わない: 検証で、日本株だけに同じルールを当てると年 +12% で、日本株を均等に持つ (+15%) より悪かった
(日本株でモメンタムが効きにくいことは以前から知られている)。今の日本株の保有は、最初の週次で売りの対象になる。

## リスク (目をつむる前に知っておくこと)

- **最大下落は 40% 前後**を見込む。40万円なら -16万円。検証では 2006・2016・2024年に -30〜37% があった
- **5銘柄に集中**: 1銘柄が決算で -30% になれば口座は -6%。売りの判定は終値、約定は翌日なので、急落は避けられない
- **為替**: 保有がすべてドル建てになる。円高が 10% 進めば、株価が同じでも -10%。検証には過去の為替が入っている
- **急騰のあとの急落に弱い**: 上がっている銘柄を買う仕組みなので、相場の主役が崩れる局面 (2022年、2026年の夏) では損が続く。
  検証上のいまの位置も、2026年夏の最高値から -25% のところ
- **検証は良く見えすぎる**: 母集団が今の大型株で、ルールも過去を見て決めている。実際の成績は検証より悪いと考える
- **NISA 枠**: 売買は年13往復ほど (約100万円/年の買付) で、成長投資枠 240万円に収まる見込み。売っても枠は戻らない

## 使い方

```bash
python -m surge plan              # 注文案 (土日は週次、平日は日次)。reports/surge/<日付>/plan.md
python -m surge plan --weekly --exclude TICKER   # 裁量で見送って作り直す
python -m surge status            # 保有・順位・目標までの進み具合
python -m surge backtest          # 過去21年の仮想売買。reports/surge/backtest/<name>/
python -m surge robust            # 設定を少し変えた16通り。成績が設定の偶然に頼っていないかを見る
python -m surge fetch --force     # 日足を取り直す
python -m pytest -q tests/test_surge.py
```

運用は surge-trade スキル (`/surge-trade`): 週末に入れ替えの注文案、平日は「高値から -25%」の確認だけ。
約定の記録は今までどおり sync-account スキル (`python -m trader record`)。

**既存の daily-trade と同じ口座を見ている。** 両方の注文案に従うと売買がぶつかるので、surge で運用する間は
daily-trade の定期実行を止める (どちらで運用するかは人が決める)。

## 作り

| ファイル | 役割 |
|---|---|
| `universe.yaml` | 母集団と業種グループ |
| `config.yaml` | ルールの数字、コストの想定、目標 |
| `data.py` | Yahoo Finance の日足の取得・キャッシュ、日米の暦をそろえた価格パネル (配当込み・円換算) |
| `strategy.py` | **ルール本体**。順位づけと `decide()` (売り・買い・減らす・買い増す) |
| `backtest.py` | 仮想売買 (翌日寄付き約定・整数株・現金の制約・コスト)、成績の集計 |
| `plan.py` | 今の口座 + `decide()` → 株数つきの注文案とレポート |
| `account.py` | `state/portfolio.json`・`settings.yaml`・`STOP` を読む |
| `cli.py` | コマンド |

検証と毎日の注文案は、同じ `strategy.decide()` を通る (`tests/test_surge.py` で確認)。
検証が「その日までのデータ」しか使っていないこともテストしている。
