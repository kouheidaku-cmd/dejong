# 事前登録: 損切り幅を値動きの大きさに合わせる (ATR 損切り) の検証 (2026-11-13)

このファイルと候補の仕様 (下記の yaml) は、**検証を1回も走らせる前に**コミットする。
結果を見てから仕様や基準を変えた場合は、その事実と理由をレポートに必ず書く。

## きっかけ

人からの指摘: AI 関連株は値動きが大きく、損切り (-8%) した後に戻ることが多い (2026-11-13 時点で、売った AMZN は +10%、VRT は +8%)。
v3 の損切りは全銘柄一律 -8% だが、1日の値動きの平均 (ATR) は銘柄によって 1.4% (BRK-B・NTT) から 6.7% (ソフトバンクG) まで5倍違う。
値動きの大きい銘柄では -8% が1〜2日のブレで当たり、小さい銘柄では -8% は広すぎる。
「損切り幅を各銘柄の ATR の何倍かにする」と良くなるかを確かめる。押し目買い (2026-11-10) とは別の案 (買い方は変えず、売り方だけ変える)。

## 候補 (すべて v3 = `config/rules.yaml` の `exit` に `stop_atr_mult` を足しただけ)

損切り幅 = **買った日 (シグナルの日) の ATR14 ÷ 終値 × k**。買った後は変えない。それ以外 (トレーリング -15%・利確 +20%・買い条件・枠) は v3 のまま。

| 候補 | k | 母集団の中央値 (ATR 2.6%) での損切り幅 | ATR 1.6% (KO など) | ATR 5.5% (VRT など) |
|---|---|---|---|---|
| `2026-11-13-s1-atr2.yaml` | 2 | 約 -5% | 約 -3% | 約 -11% |
| `2026-11-13-s2-atr3.yaml` | 3 | 約 -8% (今とほぼ同じ) | 約 -5% | 約 -17% |
| `2026-11-13-s3-atr4.yaml` | 4 | 約 -10% | 約 -6% | 約 -22% |

- ATR14 = 直近14営業日の「真の値幅」(高値 - 安値、前日終値とのギャップを含む) の平均。上の中央値は、61銘柄それぞれの過去の ATR の中央値をさらに並べた中央値 (検証の成績は見ていない)
- ATR が計算できないとき (上場直後など) は v3 の -8% を使う
- 1株あたりの損失が増える銘柄 (値動きの大きい銘柄) も、買う株数は v3 と同じ (総資産の12%)。つまり k が大きいほど1回の損失は大きくなりうる

## 評価の方法と採用の基準 (`config/strategy.md` の「ルールの直し方」、2026-11-10 版)

```bash
python -m trader phases config/rules.yaml rules/candidates/2026-11-13-s1-atr2.yaml rules/candidates/2026-11-13-s2-atr3.yaml rules/candidates/2026-11-13-s3-atr4.yaml --name 2026-11-13-atr-phases
```

1年の区切りを1月〜12月始まりの12通りに変えて、現行ルール (v3) と「同じ持ち高の指数」と比べる。

- 12通り中10通り以上で通算リターンが v3 より高く、**かつ** 12通り中10通り以上で各年の最大下落の平均が v3 より大きくない → **採用候補**
- 片方だけ満たす → 合否を付けず、差の大きさを示して**人が決める**
- どちらも10通り未満 → 不採用
- 「同じ持ち高の指数」を上回った区切りの数を、v3 の値と並べて必ず報告する
- トレード数が v3 の半分以上
- 補足として、学習期間 (前70%) の損切りの回数・損失の合計と、AI・半導体関連の銘柄での損切りの結果も報告する (判定には使わない)
- 採用候補はフォワードテスト (`config/forward.yaml`) に足して3か月以上見てから、実際の口座に使うかを人が決める

## 事前に分かっている弱点
- 過去8年のデータは21案以上で使い切っている。合否より、差の大きさと向きを見る
- 母集団が「今の大型株」なので生き残りバイアスがある。値動きの大きい銘柄の損切りを広げる案は、後から勝者と分かっている銘柄 (NVDA など) を長く持つことになり、この偏りの恩恵を受けやすい
- 損切りの判定は終値、約定は翌朝の寄付き。急落の翌朝に寄付きでさらに下げる分は、どの案でも同じように入る
