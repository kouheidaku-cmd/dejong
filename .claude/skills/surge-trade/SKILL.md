# surge の売買ルーチン (半自動)

`surge/` は既存の `trader/` (daily-trade) とは別の売買システム。米国の大型株から「いま一番強い5銘柄」に集中して持つ。
ルールと検証の数字は `surge/README.md`。**Claude は注文案を出すだけ**で、発注は人が楽天証券で行う。

- **週次 (土日)**: 入れ替えを判定する。金曜の米国市場が終わった後 (日本時間の土曜 6:30 以降) に実行する
- **日次 (平日 16:30 ごろ)**: 「買ってからの最高値から -25%」の売りだけを判定する。たいていは「注文なし」

## ルール (必ず守る)
- 売買の判断は `python -m surge plan` の出力どおり。**Claude が足してよいのは買いの見送りだけ** (下の手順4)。
  シグナルのない買い、売りの見送り、株数の変更はしない
- `state/` を手で編集しない。約定の反映は `python -m trader record` (sync-account スキル) で行う。surge は口座の記録を読むだけ
- `surge/config.yaml` の `params` は検証とセット。変えたければレポートで提案し、人の了承を得てから
  `python -m surge backtest` と `python -m surge robust` で確かめる
- リポジトリ直下に `STOP` があれば注文案は出ない。回避しない
- 既存の daily-trade と同じ口座を見ている。両方の注文案を同じ日に出さない (どちらで運用するかは人が決める)

## 手順

1. **準備**
   ```bash
   git pull --ff-only
   pip install -q -r requirements.txt
   ```

2. **注文案を作る**
   ```bash
   python -m surge plan            # 土日は週次、平日は日次になる (--weekly / --daily で指定もできる)
   ```
   `reports/surge/<日付>/plan.md` と `plan.json` ができる。まず冒頭を確認する:
   - 「**注意**: 〜の終値が…までしか取れていない」→ データが古い。時間をおいて `python -m surge fetch --force` で取り直してからやり直す。
     それでも取れないときは、注文案を出さずに理由をレポートに書く
   - 「STOP ファイルがある」→ 注文案なしで終了
   - 前回の注文案の約定がまだ記録されていない (保有が前回の `plan.md` の「保有」のまま) → 記録と実際の口座がずれている。
     新しい注文案は出さず、約定の報告 (スクショ) を頼む

3. **注文案がなければ**、手順6へ (レポートは短くてよい)

4. **買いの銘柄を確認する** (週次で買いがあるときだけ)
   買いの各銘柄を WebSearch で調べる。見送ってよいのは次の場合だけ:
   - 決算発表が約定予定日から3営業日以内にある
   - 買収される側になっている (株価が買収価格に張り付いて、もう上がらない)
   - 粉飾・訴訟・主力製品の事故など、会社の存続や業績の前提が崩れる悪材料が出ている
   見送るときは、その銘柄を外して作り直す (次の順位の銘柄が繰り上がる)。繰り上がった銘柄も同じように確認する:
   ```bash
   python -m surge plan --weekly --exclude TICKER1 TICKER2
   ```
   「割高に見える」「上がりすぎている」は見送りの理由にしない (このシステムは上がっている銘柄を買う仕組み)。

5. **注文案を人に示す** — `plan.md` の「注文案」の表をそのまま示し、発注の順番を添える:
   1. 日本株の売り → 次の営業日の朝 (寄付きまでに成行、かぶミニなら寄付取引)
   2. 米国株の売りと買い → その日の夜の米国市場で成行。買付余力が足りない買いは、売却代金が反映されてから
   3. 約定したら約定照会か保有銘柄のスクショを送ってもらう (sync-account スキルで記録)

6. **レポートとコミット**
   ```bash
   python -m surge --no-fetch status     # 目標までの進み具合 (reports/surge/journal.csv にも1行残る)
   ```
   `reports/surge/<日付>/report.md` に、注文案の表、見送った銘柄と理由 (出典つき)、status の要点、確認してほしいことを書く。
   ```bash
   git add reports/surge && git commit -m "surge: <日付> (weekly|daily)" && git push
   ```

## 見直し
- 月に1回、`python -m surge backtest` を走らせて、実際の成績 (`reports/surge/journal.csv`) が検証の幅に収まっているかを見る
- 4か月で -17% より悪い / 最高値から -40% より悪い → 検証の「悪い方5%」「最大下落」を超えている。注文案を止めて (`STOP`)、人と相談する
