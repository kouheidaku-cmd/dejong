# 日次売買ルーチン (半自動)

平日 16:30 JST ごろに1日1回実行する。日本株は当日の終値、米国株は前日 (米国時間) の終値で判断する。
`broker: manual` なので **Claude は注文案を出すだけ**。発注は人が楽天証券のアプリで行う:
- 米国株の注文案 → その日の夜の米国市場で発注
- 日本株の注文案 → 翌営業日の朝 (寄付き) に発注

## ルール (必ず守る)
- `state/` 以下を手で編集しない。口座状態は `python -m trader ...` だけが書き換える
- 注文案は必ず `python -m trader submit` を通す。リスクチェックで拒否された注文を回避・再投入しない
- `config/strategy.md` と `config/settings.yaml` は人間の管理。変更したければレポートで提案する
- 判断に迷ったら注文しない。「売買なし」は正当な結論

## 手順

1. **準備**
   ```bash
   git pull --ff-only
   pip install -q -r requirements.txt
   ```

2. **スナップショット**
   ```bash
   python -m trader prep
   ```
   出力 (= `reports/daily/<日付>/snapshot.json`) を読む。口座 (現金・総資産・ドローダウン、すべて円換算)、
   保有銘柄と指標、為替、前回の注文案のうち報告がなかったもの、ウォッチリスト銘柄の指標、リスク上限が入っている。

3. **今日やるか判定**
   - `stopped: true` (リポジトリ直下に `STOP` ファイル) → 注文案を出さず、レポートだけ書いて終了
   - `latest_bar_date.JPY` が今日でない → 日本は休場。日本株の注文案は出さない
   - `latest_bar_date.USD` が直近の米国営業日より古い → 米国株の注文案は出さない
   - `settled_orders` に `proposal_unconfirmed` がある → 前回の注文案が実行されたか不明。
     記録上の保有が実際と違う可能性があるので、該当銘柄の判断は慎重にし、レポート冒頭で確認を頼む

4. **判断材料を集める**
   - `config/strategy.md` (売買方針) を読む
   - 最新の週次レポート `reports/weekly/*/report.md` を読み、各銘柄の投資仮説を確認
   - 保有銘柄で値動きが大きいもの (|ret_1d| > 4% や volume_ratio > 2) は WebSearch でニュースを確認
   - 直近の `reports/daily/*/report.md` を2〜3日分読み、判断に一貫性を持たせる

5. **注文を決める** — `strategy.md` に沿って、保有銘柄の売り → 新規・買い増しの順に検討する。
   現金が少ないので、買いは同じ日の売却代金でまかなう前提になる (リスクチェックもそう計算する)。
   `reports/daily/<日付>/orders.json` に書く (注文なしでも空配列で書く):
   ```json
   {
     "date": "2026-10-20",
     "orders": [
       {"ticker": "VRT", "side": "sell", "qty": 1, "type": "market",
        "rationale": "取得単価から-25%、SMA50を下回り仮説(〇〇)も崩れた"}
     ],
     "notes": "全体の判断メモ"
   }
   ```
   - 日本株は `8035.T` のように `.T` 付き、米国株はティッカーのまま。数量は1株単位でよい
   - `type` は `market` か `limit` (`limit_price` は現地通貨、前日終値±10%以内)
   - `rationale` は必須。後で振り返れるように具体的に

6. **リスクチェックして注文案にする**
   ```bash
   python -m trader submit reports/daily/<日付>/orders.json
   ```
   `rejected` があれば理由を確認する。数量を減らすなど方針に沿った修正が明らかな場合に限り、
   修正版を `--force` で再提出してよい (1回まで)。

7. **日次レポート** — `reports/daily/<日付>/report.md` に書く。**冒頭は人がそのまま楽天で発注できる形にする**:
   ```markdown
   ## 今日の注文案
   | 市場 | 発注タイミング | 銘柄 | 売買 | 数量 | 注文方法 |
   |---|---|---|---|---|---|
   | 米国 | 今夜 | VRT (Vertiv) | 売 | 1株 | 成行 |
   | 日本 | 明朝 | 8035 東京エレクトロン | 買 | 5株 (かぶミニ) | 成行 |
   約定したら約定照会か保有銘柄のスクショを送ってください。
   ```
   続けて: 口座サマリー (総資産、前日比、ドローダウン、現金比率) / 各注文案の理由 / 拒否された注文と理由 /
   保有銘柄ごとの一言コメント / 確認してほしいこと (未確認の注文案など)。

8. **記録を残す**
   ```bash
   git add state reports
   git commit -m "daily: <日付>"
   git push
   ```
   状態はリポジトリにしか残らないので、push まで必ず行う。

9. **最後の返答** — 通知で読まれるので短くまとめる: 注文案の表 (なければ「今日は売買なし」) と、一言の理由。
