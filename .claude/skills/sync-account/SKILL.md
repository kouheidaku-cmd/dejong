# 口座の記録を更新する

人が楽天証券で発注した結果を記録に反映する。記録が実際の口座とずれると日次の判断が狂うので、こまめに行う。

## どちらのコマンドを使うか

| 受け取った情報 | 使うコマンド |
|---|---|
| 個別の約定 (約定照会のスクショ、「MSFTを1株530ドルで売った」など) | `record` |
| 保有銘柄の一覧 + 総合サマリー (現金がわかる) | `sync` |

両方ある場合は、`record` で約定を記録してから `sync` で残高を合わせる。

## record (1件ずつ)
```bash
python -m trader record <ticker> <buy|sell> <数量> <約定単価(現地通貨)> [--fx <約定為替>] [--fee <手数料(円)>] [--date YYYY-MM-DD]
```
- 日本株は `8035.T` のように `.T` を付ける。米国株はティッカーのまま
- 円貨決済の米国株は、約定照会に出る為替レートを `--fx` に入れる (なければ省略で最新レート)
- `--date` は約定日。省略すると今日になる
- 対応する注文案があれば自動で消える
- ルールの**利確シグナル (take_profit) による一部売り**のときだけ `--take-profit` を付ける (利確は1回だけなので、その記録になる)。入れ替えなど、それ以外の一部売りには付けない

## cashflow (入金・出金)
```bash
python -m trader cashflow -20000 --note "出金"     # 出金はマイナス、入金はプラス (円)
```
- 現金と、ドローダウンの基準になる最高値を同じだけ動かす (出入金を値下がり・値上がりと見なさない)
- 人が「〇円出金した / 入金した」と言ったら使う。sync の `reset_peak` より、こちらを優先する

## sync (一覧で上書き)
`state/sync/<日付>.yaml` を作ってから実行する:
```yaml
date: 2026-10-20
cash_jpy: 452            # 円の預り金 + 外貨預り金の円換算 (総合サマリーの「現金」「USドル」の合計)
other_assets_jpy: 20410  # 投資信託など売買対象外の資産
positions:               # 保有銘柄画面の数量と平均取得価額 (米国株はドル建てのまま)
  8035.T: {qty: 15, avg_cost: 11342.26}
  MSFT: {qty: 2, avg_cost: 386.75}
# reset_peak: true       # 入出金があったときだけ (ドローダウンの基準をリセット)
# account は口座区分 (nisa_growth / tokutei など)。書かなければ前回の値が引き継がれる
# rule_ref は書かなくてよい (前回の値が引き継がれる)。損切り・利確の基準を取得単価から変えたいと人が言ったときだけ
#   8035.T: {qty: 15, avg_cost: 11342.26, rule_ref: 10085}
```
```bash
python -m trader sync state/sync/<日付>.yaml
```
出力の `position_changes` が想定外 (記録にない売買) なら、人に確認する。

## 画像から読むときの注意
- 数量・単価は画面の数字をそのまま使い、読み取れない値は推測せずに人に聞く
- 総合サマリーの合計と、保有銘柄から計算した評価額がおおよそ合うか確かめる
- 入金・出金があったか聞き、あれば `reset_peak: true` にする

## 最後に
```bash
git add state
git commit -m "sync: <日付>"
git push
```
